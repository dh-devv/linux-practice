# 리눅스의 개요

## 리눅스의 특징
- **오픈 소스 운영체제**: 소스 코드를 확인·수정·배포할 수 있다. 단, 구체적인 권리는 각 구성 요소의 라이선스 조건을 따른다.

- **다중 사용자(multi-user)**: 여러 사용자가 한 시스템을 함께 사용할 수 있고, 사용자별 권한과 파일을 관리한다.

- **다중 작업(multi-tasking)**: 여러 프로그램을 실행하고 CPU 시간을 나누어 처리한다.

- **다중 스레드(multi-threading) 지원**: 한 프로세스 안에서 여러 실행 흐름을 만들 수 있다.

- **네트워크 기능 지원**: 네트워크 통신과 서버 운영에 필요한 기능을 제공한다.

- **이식성과 파일 시스템 지원**: 여러 하드웨어 구조와 다양한 파일 시스템을 지원한다.

- **계층적 파일 시스템**: 최상위 디렉터리 `/`에서 시작하는 트리 구조로 파일과 디렉터리를 관리한다.

### 알아둘 용어
- **프로세스(process)**: 실행 중인 프로그램과 그 실행에 필요한 자원·상태를 포함하는 단위다.

- **스레드(thread)**: 프로세스 안에서 실제 명령을 실행하는 흐름이다. 한 프로세스의 스레드들은 메모리 등 일부 자원을 공유하지만, 실행 상태와 스택은 각각 가진다. 프로세스보다 생성·전환 비용이 작은 편이지만, 자원을 공유하므로 한 스레드의 문제가 같은 프로세스의 다른 스레드에 영향을 줄 수 있다.

- **네트워크 기능**: 리눅스가 다른 컴퓨터나 인터넷과 데이터를 주고받을 수 있다는 뜻이다.

- **POSIX(Portable Operating System Interface)**: IEEE가 정한 운영체제 인터페이스 표준이다. 파일·프로세스·시스템 호출 등의 규칙을 표준화해 프로그램을 여러 유닉스 계열 운영체제에서 이식하기 쉽게 한다. 리눅스는 POSIX와 높은 호환성을 제공하지만 모든 구현이 완전히 동일하다는 뜻은 아니다.

## 장점과 고려할 점
### 장점
- 소스 코드가 공개되어 목적에 맞게 수정·구성할 수 있고, 다양한 배포판 중 선택할 수 있다.

- 다중 사용자·다중 작업, 네트워크와 서버 운영을 지원한다.

- 안정성, 보안, 성능은 시스템 구성과 관리 방식에 따라 높은 수준으로 운용할 수 있다.

- 여러 하드웨어와 파일 시스템을 지원한다.

### 고려할 점
- 배포판과 환경에 따라 사용법이 달라 초보자에게 학습 부담이 있을 수 있다.

- 일부 상용 프로그램·장치의 지원 여부가 운영체제나 제조사에 따라 다를 수 있다.

- 기술 지원의 범위와 비용은 배포판·제품·지원 계약에 따라 다르다.

- 공개 소프트웨어라고 해서 자동으로 안전한 것은 아니다. 보안 업데이트와 적절한 설정이 필요하다.

> 장단점은 절대적인 속성이 아니다. 시험에서는 특징을 구분해 기억하고, 실제 성능·보안은 설정과 관리에 따라 달라진다는 점도 함께 이해한다.

## 파일 시스템과 주요 디렉터리

### 디렉터리와 경로
- **디렉터리(directory)**는 파일과 하위 디렉터리를 묶어 관리하는 공간이다.

- 리눅스의 디렉터리 구조는 `/`를 꼭대기로 하는 계층적 트리 구조다. 경로 구분 기호는 슬래시(`/`)를 사용한다.

- `/`는 **최상위 디렉터리**이고, `/root`는 **root 사용자의 홈 디렉터리**다. 둘은 서로 다르다.

### 자주 출제되는 디렉터리

| 경로 | 주요 역할 | 기억할 점 |
|---|---|---|
| `/` | 최상위 디렉터리 | 모든 파일과 디렉터리가 이 아래에 위치 |
| `/boot` | 부팅에 필요한 파일 | 커널 이미지, 부트로더 관련 파일 등 |
| `/etc` | 시스템 및 서비스 설정 파일 | 일반적으로 실행 파일이 아니라 설정 파일 |
| `/home` | 일반 사용자 홈 디렉터리 | 사용자별 개인 파일과 설정 |
| `/root` | root 사용자의 홈 디렉터리 | `/`와 혼동하지 않기 |
| `/bin` | 시스템의 기본 명령어 | 전통적인 디렉터리 구분. 최신 배포판에서는 `/usr/bin`과 통합되기도 함 |
| `/sbin` | 시스템 관리용 기본 명령어 | 전통적인 구분이며 `/usr/sbin`과 통합되기도 함 |
| `/lib` | 기본 명령어 실행에 필요한 공유 라이브러리·커널 모듈 등 | 최신 배포판에서는 `/usr/lib`와 통합되기도 함 |
| `/dev` | 장치를 나타내는 파일 | 디스크·터미널 등 장치에 접근하는 인터페이스 |
| `/proc` | 프로세스 및 커널 정보를 제공하는 가상 파일 시스템 | 실제 일반 파일을 저장하는 곳이 아님 |
| `/sys` | 장치·커널 정보를 제공하는 가상 파일 시스템 | 커널과 장치 정보를 노출 |
| `/var` | 계속 변할 수 있는 데이터 | 로그, 메일, 캐시, 스풀 등 |
| `/tmp` | 임시 파일 | 재부팅 또는 정리 정책에 따라 삭제될 수 있음 |
| `/usr` | 대부분의 사용자 공간 프로그램·라이브러리·문서 등 | 일반 사용자의 홈은 `/home`이며, `/usr`과 다름 |
| `/usr/local` | 로컬에서 별도로 설치한 프로그램과 데이터 | 배포판 관리 파일과 구분해 사용하는 경우가 많음 |
| `/opt` | 추가 설치 소프트웨어 패키지 | 선택적·부가 소프트웨어 |
| `/mnt` | 파일 시스템을 임시로 마운트할 때 사용하는 위치 | 관리자가 임시 마운트 지점으로 자주 사용 |
| `/media` | 이동식 매체의 마운트 지점으로 사용하는 위치 | 자동 마운트 환경에서 자주 사용 |
| `/run` | 부팅 후 실행 중인 시스템의 휘발성 상태 정보 | 재부팅하면 내용이 초기화되는 경우가 일반적 |
| `/lost+found` | 파일 시스템 검사·복구 과정에서 발견된 파일 조각 등을 보관 | 주로 ext 계열 파일 시스템의 각 파일 시스템에 존재 |

> `/bin`, `/sbin`, `/lib`와 `/usr`의 관계는 최신 배포판에서 통합(merged `/usr`)되어 실제 경로가 심볼릭 링크일 수 있다. 시험의 기본 역할 구분과 현대 배포판의 구현을 함께 알아둔다.

## 리눅스 배포판

### 개념
- **리눅스 커널**은 운영체제의 핵심으로 하드웨어와 프로그램 사이의 자원을 관리한다.

- **리눅스 배포판(distribution)**은 리눅스 커널에 시스템 도구, 라이브러리, 설치 프로그램, 패키지 관리 도구, 응용 프로그램 등을 묶어 사용 가능한 운영체제 형태로 제공하는 것이다.

- 배포판마다 구성 소프트웨어, 기본 설정, 패키지 형식, 지원 정책이 다를 수 있다.

### 주요 계열과 배포판

| 계열·분류 | 대표 배포판 | 시험 대비 핵심 |
|---|---|---|
| 독립형 | Slackware | 다른 주요 배포판 계열에서 파생되지 않은 대표적인 배포판. 오래된 배포판으로 자주 소개됨 |
| Debian 계열 | Debian, Ubuntu | Debian/Ubuntu는 `.deb` 패키지와 APT 계열 도구를 사용한다. Ubuntu는 Debian을 기반으로 한다 |
| Red Hat 계열 | Fedora, RHEL, CentOS Stream, Rocky Linux | RPM 계열 패키지를 사용한다. Fedora는 RHEL과 밀접한 관계의 커뮤니티 배포판이고, RHEL은 기업용 배포판이다 |
| SUSE 계열 | openSUSE, SLES | RPM 패키지와 Zypper를 사용한다. SLES는 기업용 배포판이다 |

#### 계열 관계에서 헷갈리기 쉬운 점
- **Fedora와 RHEL**: Fedora는 RHEL과 관련된 커뮤니티 배포판이다. 전통적인 시험 자료에서는 RHEL의 기반 또는 선행 배포판으로 설명하기도 한다.

- **CentOS와 CentOS Stream**: 기존 CentOS Linux는 RHEL과 호환되는 재구성 배포판이었다. CentOS Stream은 RHEL의 다음 마이너 버전을 위한 개발 흐름에 해당하므로 기존 CentOS Linux와 같은 방식의 하위 호환 배포판으로 외우면 안 된다.

- **Rocky Linux**: RHEL과의 호환성을 목표로 하는 기업용 리눅스 배포판이다.

- **Ubuntu 데스크톱 환경**: 예전 Ubuntu는 Unity를 기본으로 사용했지만, 현재 Ubuntu의 기본 데스크톱은 GNOME이다. Unity는 과거 버전과 연결해 기억한다.

- 배포판의 지원 정책과 관계는 바뀔 수 있다. 시험에서는 최신 출제 범위와 교재의 기준 연도를 확인한다.

## 시험 대비 정리

### 현재 메모만으로 충분할까?
이 주제만 놓고 보더라도 **처음 적은 요약만 암기하는 것으로 합격을 보장하기는 어렵다.** 특히 디렉터리 역할, POSIX·스레드의 의미, 배포판의 계열 관계를 구분하는 문제가 나올 수 있다. 위 표의 핵심을 외우고, 각 항목을 설명할 수 있는지 확인하는 것이 좋다. 다만 실제 합격 여부는 전체 시험 범위와 문제 풀이 수준에도 달려 있다.

### 우선 암기할 항목
1. 리눅스의 기본 특징: 오픈 소스, 다중 사용자, 다중 작업, 다중 스레드 지원, 네트워크 기능, 계층적 파일 시스템.

2. 용어 구분: 프로세스와 스레드, 최상위 디렉터리 `/`와 root 사용자의 홈 `/root`, 리눅스 커널과 배포판.

3. 디렉터리 역할: `/boot`, `/etc`, `/home`, `/root`, `/bin`, `/sbin`, `/dev`, `/proc`, `/var`, `/tmp`, `/usr`, `/lost+found`.

4. 배포판 계열: Debian–Ubuntu, Red Hat–Fedora/RHEL/CentOS Stream/Rocky Linux, SUSE–openSUSE/SLES, 독립형 Slackware.

5. 패키지 연결: Debian·Ubuntu는 `.deb`/APT, Red Hat·SUSE 계열은 RPM 계열. 세부 패키지 관리 명령은 별도 단원에서 함께 학습한다.

### 스스로 확인하기
- `/`와 `/root`는 어떻게 다른가?

- 프로세스와 스레드는 어떤 관계인가?

- `/etc`, `/var`, `/proc`, `/dev`에는 각각 어떤 종류의 정보가 있는가?

- Debian과 Ubuntu, Fedora와 RHEL은 어떤 관계인가?

- CentOS Stream을 기존 CentOS Linux와 동일한 배포판이라고 할 수 있는가?

- POSIX가 표준화하려는 것은 무엇인가?

답을 보지 않고 설명할 수 없다면 해당 표를 다시 복습한 뒤 기출 문제로 확인한다.
