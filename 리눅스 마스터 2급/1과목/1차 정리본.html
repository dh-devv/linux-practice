PART 1. 리눅스의 개요 · 역사 · 라이선스

글 대신 구조도와 타임라인으로 암기

1-1. 리눅스 시스템 양파 구조 (Kernel vs Shell vs 배포판) 개념 1순위

👤 사용자 & 응용 프로그램 (X Window, 웹브라우저, 편집기)
🐚 셸 (Shell: bash, sh, csh, zsh) — 명령어 해석기
⚙️ 커널 (Kernel: Linux) — 자원 제어·스케줄링·동적 모듈(LKM)
💻 물리 하드웨어 (CPU, RAM, Disk, NIC)

핵심 요약 3줄 컷

• 커널(Kernel): 토르발스가 개발. 하드웨어 직접 제어. 모놀리식(단일형) 커널이지만 실행 중 modprobe, insmod, rmmod로 모듈을 동적 추가/제거 가능!

• 셸(Shell): 사용자의 명령어를 해석해 커널에 전달. 리눅스 기본 표준은 bash(Bourne Again Shell).

• 배포판: Linux 커널 + GNU 유틸리티(GCC, bash 등) + 패키지 관리자를 묶은 완제품.

🚨 오답 함정: "셸이 하드웨어를 직접 제어한다"(X → 커널 역할) / "모놀리식 커널이라 실행 중 모듈 추가가 불가능하다"(X → 동적 모듈 적재 가능)

1-4. 오픈소스 라이선스 신호등 비교표 (FSF vs OSI) 법적 조건 주의

🕊️ FSF (자유 소프트웨어 재단, 스톨먼)

• 4대 자유: 실행(0) · 학습/개작(1) · 복제배포(2) · 개선본배포(3)
• 윤리적 자유 강조. 상업적 유료 판매도 허용!

⚙️ OSI (오픈소스 이니셔티브, 1998 레이먼드)

• 'Free=공짜' 오해 방지 위해 Open Source 용어 채택
• OSD(오픈소스 정의 10대 조건) 제정, 기업 참여·실용성 강조

라이선스 외부 배포 시 소스 공개 범위 독점(상용) SW 결합/비공개 가능 여부 및 핵심 포인트
GPL (v2/v3) 🔴 외부 배포 시 전체 파생물 소스 공개 • 리눅스 커널은 GPLv2. (GPLv3는 하드웨어 잠금 티보이제이션 방지 추가)
• 내부에서만 수정·사용하고 배포 안 하면 공개 의무 없음!
AGPL 🔴 배포 + 네트워크(웹/클라우드) 서비스 시에도 공개 • 서버에서 실행만 할 때 GPL 공개 의무가 비켜가는 허점을 막음
LGPL 🟡 라이브러리 수정분만 공개 • 단순 동적 링크(Linking)한 독점 응용프로그램 자체 소스는 비공개 허용!
MPL 🟡 수정한 MPL 파일만 공개 • 모질라(넷스케이프) 제정. 별도 파일로 작성한 독점 코드는 비공개 가능
BSD / MIT / Apache 🟢 소스 공개 의무 없음 (Permissive) • 저작권 고지만 유지하면 수정본을 완전히 비공개 상용화 가능
• Apache는 명확한 특허권 허여 및 특허 소송 방지 조항 포함

PART 2. 설치 · 디스크 · 파티션 · `/etc/fstab` · 부트 매니저

눈으로 보는 파티션 블록 & 설정 파일 분해

2-1. 디스크 인터페이스 & 파티션 번호 다이어그램 (MBR vs GPT) 시험 최빈출

IDE (PATA) 구형

• 40핀 커넥터 (40가닥 or 80가닥 전선)
• Primary Master/Slave: /dev/hda, /dev/hdb
• Secondary Master/Slave: /dev/hdc, /dev/hdd

병렬 SCSI / SATA / SAS / USB

• 장치명: /dev/sda, /dev/sdb ...
• 파티션: /dev/sda1, /dev/sda2
• 병렬 SCSI: 양끝 종단저항, 컨트롤러 ID 7(최우선)

NVMe (PCIe 고속 SSD)

• 장치명: /dev/nvme0n1 (숫자로 끝남)
• 파티션은 p가 붙음!
→ /dev/nvme0n1p1, p2

📊 MBR (msdos) 디스크의 주 파티션 · 확장 파티션 · 논리 파티션 번호 법칙 (최대 2TB 한계)

주 파티션 1
/dev/sda1
주 파티션 2
/dev/sda2
확장 파티션 (주 파티션 자리 1개 사용: /dev/sda3, 컨테이너 역할)
첫 논리: /dev/sda5 두 번째 논리: /dev/sda6

MBR 핵심 법칙

• 주 파티션 최대 4개(1~4번 예약), 확장 파티션은 최대 1개만 가능.
• 논리 파티션은 앞에 주 파티션이 몇 개든 무조건 5번부터 시작!

GPT & RAID 기초

• GPT: 2TB 초과 대용량 지원, 기본 128개 파티션 구성. UEFI 표준이나 GRUB 사용 시 BIOS에서도 부팅 가능!
• RAID: RAID 0(스트라이핑, 고장복구불가) / RAID 1(미러링) / RAID 5(최소 3개, 단일 패리티) / RAID 6(최소 4개, 이중 패리티)
• LVM 순서: 물리볼륨(PV) → 볼륨그룹(VG) → 논리볼륨(LV)

2-2. 파일 시스템 비교 & `/etc/fstab` 6개 필드 컬러 해부도 누락 완벽 보강

ext2

비저널링 (구형). 비정상 종료 시 fsck 오래 걸림

ext3

저널링 도입 (`mke2fs -j`). 빠른 복구 지원

ext4

저널링 + 익스텐트. 단일파일 16TB, 볼륨 1EiB

XFS

64비트 고성능 저널링. RHEL 7+ 기본 FS

🔍 부팅 시 자동 마운트 설정 파일: /etc/fstab 6개 필드 구조 (※ 현재 마운트 상태 기록 파일은 /etc/mtab)

① UUID=... (또는 /dev/sdb1)[1] 파일시스템 장치명/UUID/LABEL
② /home[2] 마운트 포인트(경로)
③ ext4[3] 파일시스템 종류(ext4, xfs, swap)
④ defaults,usrquota[4] 마운트 옵션 (핵심!)
⑤ 1 (또는 0)[5] dump 백업 여부 (0:안함, 1:함)
⑥ 2 (0/1/2)[6] fsck 점검 순서 (0:안함, 1:루트, 2:기타)

[4번째 필드] `/etc/fstab` 필수 마운트 옵션 암기

• defaults: rw, suid, dev, exec, auto, nouser, async 7가지 기본 속성을 한 번에 부여
• auto / noauto: 부팅 시(또는 mount -a 실행 시) 자동 마운트 여부 | ro(읽기전용) / rw(읽기·쓰기)
• exec / noexec: 바이너리 실행 허용 여부 | suid / nosuid: SetUID/SetGID 허용 여부 | usrquota / grpquota: 디스크 쿼터 활성화

# 디스크/파일시스템 핵심 명령어 한눈에 보기
fdisk -l                    # 파티션 테이블 확인 (fdisk 대화형 키: n 생성, d 삭제, p 출력, t 타입변경[82:swap, 83:Linux, 8e:LVM], w 저장, q 취소)
mkfs -t ext4 /dev/sdb1      # 파일시스템 포맷 (= mkfs.ext4 /dev/sdb1, XFS는 mkfs.xfs -f /dev/sdb1)
mkswap /dev/sdb2 && swapon /dev/sdb2   # 스왑 포맷 후 활성화 (해제는 swapoff, 확인은 free 또는 swapon -s)
mount -t ext4 /dev/sdb1 /mnt           # 마운트 (해제는 umount /mnt  ← 철자 unmount 아님 주의!)
df -h (-i: inode 확인, -T: FS유형 표시)  # 마운트된 디스크의 전체/남은 용량 확인  vs  du -sh /var (특정 디렉터리 실제 사용량 합산)

3-2. 권한(Permission) · 특수 권한 · 라이브 `umask` 계산기 직접 눌러서 확인

SetUID (8진수 4000, u+s)

• 소유자 실행 자리에 s (원래 x 없으면 대문자 S)
• 실행 중 파일 소유자(root) 권한 부여
• 대표 파일: /usr/bin/passwd (4755)

SetGID (8진수 2000, g+s)

• 그룹 실행 자리에 s (x 없으면 S)
• 디렉터리에 설정 시 내부 생성 파일의 소유 그룹이 디렉터리 그룹으로 자동 상속

Sticky Bit (8진수 1000, o+t)

• 기타 실행 자리에 t (x 없으면 T)
• 파일 소유자·디렉터리 소유자·root만 삭제/이름변경 가능
• 대표 디렉터리: /tmp (1777, drwxrwxrwt)

🧮 인터랙티브 `umask` 비트 제거 시뮬레이터 (단순 뺄셈 함정 체험!)

공식: 최종권한 = 기본모드 & (~umask). 홀수 umask(예: 023, 001)를 입력해 일반 파일(기본 666)에서 왜 뺄셈이 틀리는지 바로 확인해 봐!

일반 파일(666): 644 (rw-r--r--)
디렉터리(777): 754 (rwxr-xr--)

3-3. 배시(bash) 환경 설정 파일 실행 순서 플로우차트 누락 완벽 보강

시스템 전체 적용(/etc/*) vs 개인 사용자 적용(~/*), 그리고 로그인 셸(Login Shell)로 들어올 때의 실행 순서:

① /etc/profile시스템 전체 로그인 환경변수
(/etc/profile.d/*.sh 호출)
➜
② ~/.bash_profile개인 로그인 설정
(없으면 ~/.bash_login → ~/.profile 순 탐색)
➜
③ ~/.bashrc개인 별칭(alias)·함수
(비로그인 새 터미널 열 때도 실행)
➜
④ /etc/bashrc시스템 전체 별칭·셸 함수
(데비안은 /etc/bash.bashrc)

※ 로그아웃 시 실행되는 파일: ~/.bash_logout | 수정한 설정 파일을 재로그인 없이 현재 셸에 즉시 반영하는 명령어: source 파일명 (또는 . 파일명)

PART 4. 디렉터리 · 파일 조작 · 링크 · 검색 · 압축

FHS 트리 맵 & 하드링크 vs 심볼릭링크 직관 비교

4-1. 리눅스 최상위 디렉터리 맵 (FHS) 한눈에 보기

/bin & /sbin

필수 기본 명령어(/bin) vs 시스템 관리자용 명령어(/sbin: fdisk, fsck 등)

/etc

시스템 환경 설정 파일 모음 (passwd, fstab, resolv.conf 등)

/proc ⭐

디스크가 아닌 메모리 기반 가상 파일시스템 (실시간 프로세스·cpuinfo·meminfo)

/var

가변 데이터: 시스템 로그(/var/log), 메일/프린터 스풀(/var/spool)

/dev

하드웨어 장치 파일 (sda, tty, 블랙홀 /dev/null)

/tmp

공용 임시 파일 디렉터리 (Sticky Bit 적용: 1777)

/root vs /home

관리자 root 전용 홈(/root) vs 일반 사용자 홈(/home/계정)

/lost+found

비정상 종료 후 fsck가 복구한 고아 파일 조각 보관소

4-2. 하드 링크(Hard Link) vs 심볼릭 링크(Symbolic Link) 구조도 100% 구분

🔗 하드 링크: ln a.txt hard.txt

[a.txt] ──┐
          ├──▶ [동일 inode #105] ──▶ [실제 데이터 블록]
[hard.txt]┘

• 원본과 inode 번호가 완전히 같음!
• 원본(a.txt)을 삭제해도 hard.txt로 데이터 정상 읽기 가능!
• 제약: 다른 파티션(파일시스템) 간 생성 불가, 디렉터리 대상 생성 불가.

👉 심볼릭 링크: ln -s a.txt sym.txt

[sym.txt (새 inode #209, l---------)] ──(경로 가리킴)──▶ [a.txt (#105)]

• 윈도우 '바로가기' 개념. 원본과 다른 새로운 inode 생성.
• 원본(a.txt)을 삭제하면 깨진 링크가 되어 접근 불가!
• 장점: 다른 파티션 간 생성 가능, 디렉터리 대상 생성 가능.

4-3. 파일 조작 · `find` 검색 · `tar` 아카이브 & 압축률 서열 필수 옵션

파일/디렉터리 조작 핵심 옵션

• ls: -a(숨김파일 모두), -l(상세), -i(inode 번호), -d(디렉터리 자체 정보), -R(하위 재귀), -F(파일유형 기호: 디렉터리/, 실행*, 링크@)
• mkdir -p a/b/c: 중간 상위 디렉터리까지 한 번에 생성
• rmdir: 비어있는 디렉터리만 삭제 가능 (파일 있으면 rm -rf)
• cp: -r(디렉터리 복사), -p(소유자·권한·시간 보존), -a(아카이브 완벽 보존)
• touch: 빈 파일(0B) 생성 또는 기존 파일의 시간(atime/mtime)만 갱신(내용 삭제 안 함!)

📦 압축률 서열 & `tar` 옵션 공식

• 압축률(낮음→높음): compress(.Z) < gzip(.gz) < bzip2(.bz2) < xz(.xz) (xz가 압축률 최고!)
• tar 동작: -c(생성), -x(해제), -t(목록확인), -r(파일추가)
• tar 압축 옵션: -z(gzip), -j(bzip2), -J(대문자, xz)
• -f 파일명: -f 바로 뒤에 아카이브 파일명이 인수로 와야 함! (-C 경로: 풀 디렉터리 지정)

# 실시간 파일 검색의 제왕 find 핵심 패턴
find /var/log -name "*.log" -type f -size +50M -mtime +7 -exec rm -f {} \;
# -name(이름), -user(소유자), -type(f:일반파일, d:디렉터리, l:링크), -size(+초과/-미만), -perm(권한), -mtime(수정일수), -exec 명령 {} \;

5-3. 프로세스 · 시그널(Signal) · 우선순위(Nice) 시그널 번호 필수

필수 시그널 번호 5총사

• 1번 SIGHUP: 터미널 연결 끊김 (기본은 종료이나, 데몬에서는 설정 파일 재읽기 Reload에 활용 / 로그아웃 무시 실행은 nohup 명령 &)
• 2번 SIGINT: Ctrl + C (포그라운드 작업 중단/종료)
• 9번 SIGKILL: 즉시 강제 종료 (kill -9 PID, 무시 불가)
• 15번 SIGTERM: kill 명령의 기본(Default) 시그널! (정상 종료 요청)
• 20번 SIGTSTP: Ctrl + Z (일시 중지 → jobs 확인 → bg / fg 전환)

우선순위 `nice` vs `renice` (범위: `-20` ~ `19`)

• 숫자가 작을수록(-20) 우선순위가 가장 높음! (기본값 0)
• 음수(우선순위 상향) 설정은 오직 root만 가능.
• nice -n 10 명령어: 새 프로세스 실행 시 조정 (옵션 생략 시 기본 +10)
• renice -n -5 -p PID: 이미 실행 중인 프로세스의 NI값을 PID로 변경
• ※ kill은 PID 대상, killall / pkill은 프로세스 이름 대상!

PART 6. 전 범위 스피드 실전 모의고사 (25문항)

보강된 지엽적 문항까지 완벽 수록 · 클릭 즉시 채점
Q1. 리눅스의 역사와 커널 구조에 대한 설명으로 옳은 것은?
정답: ③ | ① 1969년 최초 UNIX는 어셈블리어였고 1973년에 C언어로 재작성됨. ② 리눅스는 modprobe 등으로 동적 커널 모듈(LKM) 적재가 가능함. ④ 하드웨어 제어는 커널, 명령어 해석은 셸의 역할.
Q2. 오픈소스 라이선스에 대한 설명으로 가장 올바른 것은?
정답: ② | ① GPL 공개 의무는 외부에 '배포'할 때만 발생함. ③ BSD/MIT는 비공개 상용화가 가능한 허용적(Permissive) 라이선스. ④ 상업적 판매도 허용됨.
Q3. 리눅스 배포판에 대한 설명으로 틀린 것은?
정답: ④ | Ubuntu와 Kali Linux는 데비안(Debian) 계열이며 dpkg, apt를 사용한다.
Q4. MBR(msdos) 디스크인 /dev/sda에 주 파티션 1개와 확장 파티션 1개를 만든 뒤, 그 안에 첫 번째 논리 파티션을 생성했을 때 부여되는 장치명은?
정답: ③ | MBR에서 1~4번은 주/확장 파티션 예약 번호이므로 논리 파티션은 무조건 5번(/dev/sda5)부터 시작한다.
Q5. 디스크, GPT 파티션, 파일 시스템에 대한 설명으로 옳은 것은?
정답: ① | ② ext2는 비저널링 파일 시스템이다. ③ GRUB의 BIOS Boot Partition을 통해 BIOS에서도 GPT 부팅이 가능하다. ④ 40핀 커넥터에 80가닥 전선이다.
Q6. /etc/fstab 파일의 6개 필드 구조와 옵션에 대한 설명으로 틀린 것은?
정답: ② | 6번째 필드 값이 0일 때 점검을 생략하며, 1은 루트(/) 파일시스템 최우선 점검, 2는 그 외 파일시스템 점검이다.
Q7. 부트 매니저 GRUB과 런레벨(Runlevel)에 대한 설명으로 옳은 것은?
정답: ④ | 런레벨 3이 CLI(multi-user.target), 런레벨 5가 GUI(graphical.target)이다.
Q8. 사용자 관리 명령어와 관련 파일에 대한 설명으로 옳은 것은?
정답: ③ | ① 소문자 -g가 1차 기본그룹, 대문자 -G가 2차 보조그룹. ② 계정명 변경은 usermod -l(-n은 groupmod). ④ 템플릿 디렉터리는 /etc/skel이다.
Q9. 현재 umask 값이 0023일 때, 새로 생성되는 일반 파일(기본 0666)과 디렉터리(기본 0777)의 8진수 권한은?
정답: ② | 일반 파일(666 = rw-rw-rw-)은 원래 실행(x=1) 비트가 없으므로 기타 사용자의 3(w+x) 비트를 제거하면 w(2)만 빠져 644가 된다. 디렉터리(777)는 754가 된다.
Q10. 특수 권한(SetUID, SetGID, Sticky Bit)에 대한 설명으로 옳은 것은?
정답: ① | ② /usr/bin/passwd는 SetUID(4000)가 설정됨. ③ 원래 x가 없으면 대문자 S 또는 T로 표시됨.
Q11. 사용자가 텍스트 콘솔에서 로그인(Login Shell)할 때 bash가 가장 먼저 실행하는 시스템 전역 프로파일 설정 파일은?
정답: ④ | 로그인 시 /etc/profile이 가장 먼저 실행된 후 ~/.bash_profile → ~/.bashrc → /etc/bashrc 순으로 호출된다.
Q12. 하드 링크와 심볼릭 링크에 대한 설명으로 옳은 것은?
정답: ③ | 하드 링크는 동일 inode를 공유하며 원본 삭제 시에도 읽을 수 있지만, 다른 파티션 간 및 디렉터리 대상 생성은 불가능하다.
Q13. 디렉터리 및 파일 명령어에 대한 설명으로 틀린 것은?
정답: ② | 기존 파일에 touch를 실행하면 내용은 유지된 채 시간 정보(atime, mtime)만 갱신된다.
Q14. 압축 유틸리티와 tar 명령어에 대한 설명으로 옳은 것은?
정답: ① | ② gzip은 -z, bzip2는 -j, xz는 -J이다. ③ 목록 확인은 -t이다. ④ -f 바로 뒤에 아카이브 파일명이 왔으므로 정상 실행된다.
Q15. 현재 디렉터리 하위에서 소유자가 root이고 권한이 4755인 일반 파일을 찾는 올바른 find 명령어는?
정답: ④ | 소유자 이름 검색은 -user, 권한 검색은 -perm, 일반 파일 유형은 -type f이다.
Q16. 텍스트 처리 명령어의 옵션 설명으로 옳은 것은?
정답: ③ | ① 빈 줄 제외 행 번호는 cat -b, 빈 줄 포함 전체 행 번호는 cat -n이다. ② grep -v는 해당 패턴을 제외한 행을 반전 출력한다. ④ 행 수는 wc -l이다.
Q17. vi 편집기에서 행 번호를 표시하는 실행 모드 명령(㉠)과, 현재 커서 줄 바로 위에 빈 줄을 삽입하며 입력 모드로 전환하는 명령키(㉡)의 조합은?
정답: ② | 행 번호 표시는 :set number(:set nu)이며, 윗줄 삽입은 대문자 O(아랫줄은 소문자 o)이다.
Q18. 프로세스 시그널과 작업 제어에 대한 설명으로 옳은 것은?
정답: ④ | ① kill의 기본 시그널은 15번(SIGTERM)이다. ② kill이 PID, killall이 프로세스 이름을 받는다. ③ Ctrl+C는 SIGINT(2번), Ctrl+Z가 SIGTSTP(20번)이다.
Q19. 프로세스 우선순위(Nice)에 대한 설명으로 가장 올바른 것은?
정답: ① | 이미 실행 중인 프로세스의 NI값을 PID로 변경할 때는 renice를 사용한다.
Q20. 리눅스에서 DNS 네임서버의 IP 주소(nameserver)를 설정하는 파일(㉠)과, 레드햇 계열의 네트워크 인터페이스 설정 파일(ifcfg-*)에서 부팅 시 인터페이스를 자동 활성화하도록 지정하는 항목(㉡)은?
정답: ③ | DNS 서버 지정 파일은 /etc/resolv.conf이며, 부팅 시 자동 활성화 옵션은 ONBOOT=yes이다.
Q21. 현재 시스템에 로그인해 있는 모든 사용자의 터미널에 공지 메시지를 일괄 전송하는 명령어(㉠)와, 다른 일반 사용자가 보내는 write 메시지 수신을 거부/허용하는 명령어(㉡)는?
정답: ② | 전체 사용자 메시지 전송은 wall(Write All), 메시지 수신 허용/거부 설정은 mesg y / mesg n이다.
Q22. 셸 환경변수, 별칭, 히스토리에 대한 설명으로 옳은 것은?
정답: ④ | 환경변수 등록은 export, 별칭 해제는 unalias, 직전 명령 재실행은 !!이다.
Q23. 디스크 용량 및 파일 시스템 점검 명령어에 대한 설명으로 옳은 것은?
정답: ① | ② 마운트 해제는 umount. ③ 파일 시스템 점검/복구는 fsck. ④ blkid는 블록 장치의 UUID와 파일시스템 타입을 출력한다.
Q24. 파이프라인 중간에서 표준 출력을 화면에 보여주는 동시에 파일로도 저장하는 명령어는?
정답: ③ | tee는 T자 배관처럼 표준 출력을 화면과 파일 양쪽으로 동시에 보낸다(tee -a는 파일 끝에 이어쓰기).
Q25. 시스템 정보를 확인하거나 종료하는 명령어에 대한 설명으로 틀린 것은?
정답: ④ | which는 오직 $PATH 환경변수에 등록된 경로에서 실행 파일만 찾는다. 바이너리·소스·매뉴얼을 함께 찾는 것은 whereis, 전체 실시간 탐색은 find이다.
