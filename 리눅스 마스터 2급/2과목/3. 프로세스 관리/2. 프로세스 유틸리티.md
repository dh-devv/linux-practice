# 프로세스 관리 유틸리티

> [학습 웹 페이지](https://dh-devv.github.io/linux-practice/)의 프로세스 조회, 작업 제어, 스케줄링을 정리했습니다.

## 1. 프로세스 조회

```bash
ps
ps aux | grep sshd
pstree -p
top
```

| 명령 | 역할 |
| --- | --- |
| `ps` | 실행 중인 프로세스의 상태 출력 |
| `ps aux` | 여러 프로세스의 상세 정보 출력 |
| `pstree -p` | 부모·자식 관계를 트리로 표시하고 PID도 출력 |
| `top` | CPU·메모리와 프로세스 상태를 주기적으로 표시. `q`로 종료 |

`ps aux`의 `USER`, `PID`, `%CPU`, `%MEM`, `TTY`, `STAT`, `COMMAND`는 각각 소유자, 식별 번호, 자원 사용률, 터미널, 상태, 명령입니다. 상태에는 실행 중인 `R`, 대기 중인 `S`, 정지된 `T`, 종료 후 회수되지 않은 `Z` 등이 있습니다.

## 2. 작업 제어

| 명령·키 | 기능 |
| --- | --- |
| 명령 뒤 `&` | 백그라운드 실행 |
| `Ctrl+Z` | 포그라운드 작업 일시 정지 |
| `jobs` | 현재 셸의 작업 목록 확인 |
| `bg %1` | 1번 작업을 백그라운드에서 계속 실행 |
| `fg %1` | 1번 작업을 포그라운드로 전환 |
| `Ctrl+C` | 포그라운드 작업에 인터럽트 |

웹 자료의 `[1] Stopped vi`에서 `1`은 **작업 번호**입니다. PID와 혼동하지 마세요.

`nohup 실행파일 &`는 터미널이 종료되어도 작업이 계속되도록 하는 예시입니다. 실제 실행 파일과 출력 위치를 확인하고 사용하세요.

## 3. 우선순위와 시그널

| 명령 | 역할 |
| --- | --- |
| `nice -n 10 top` | 지정한 nice 값으로 새 프로그램 실행 |
| `renice` | 이미 실행 중인 프로세스의 nice 값 변경 |
| `kill -l` | 시그널 목록 확인 |
| `kill` | PID로 시그널 전송 |
| `killall` | 이름으로 프로세스에 시그널 전송 |

웹 자료는 nice 값의 범위를 `-20`~`19`로, 값이 작을수록 우선순위가 높다고 설명합니다. `kill -9 PID`는 강제 종료이므로 실제 PID에 무심코 사용하지 않습니다. `killall`은 같은 이름의 여러 프로세스에 영향을 줄 수 있습니다.

## 4. 반복 작업: cron

`cron`은 정해진 시간에 작업을 반복 실행합니다. 웹 자료의 관련 데몬은 `crond`, 시스템 설정 파일은 `/etc/crontab`입니다.

| 명령 | 기능 |
| --- | --- |
| `crontab -l` | 현재 사용자의 예약 작업 확인 |
| `crontab -e` | 예약 작업 편집 |
| `crontab -r` | 예약 작업 제거 |

사용자 crontab의 시간 필드는 다음 순서입니다.

```text
분 시 일 월 요일 명령
30 2 * * 0 /home/cron.sh
```

예시는 매주 일요일 오전 2시 30분에 `/home/cron.sh`를 실행합니다. `*`는 해당 필드의 모든 값을 뜻합니다. 웹 자료의 `/etc/crontab`처럼 **시스템 crontab**에서는 명령 앞에 사용자 필드가 추가됩니다. 예약을 실제 등록하기 전에 대상과 파일 형식을 확인하세요.
