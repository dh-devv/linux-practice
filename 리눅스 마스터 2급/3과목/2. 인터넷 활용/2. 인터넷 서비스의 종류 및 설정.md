# 인터넷 서비스의 종류 및 설정

> [학습 웹 페이지](https://dh-devv.github.io/linux-practice/)의 인터넷 서비스와 네트워크 설정을 정리했습니다. 설정 파일 경로와 명령은 웹 자료의 배포판 예시이며, 변경 전 현재 시스템의 네트워크 관리 방식을 확인하세요.

## 1. 인터넷 서비스

| 서비스 | 역할 | 웹 자료의 기본 포트 |
| --- | --- | --- |
| 웹 HTTP | 웹 클라이언트와 서버의 요청·응답 | 80 |
| FTP | 파일 전송 | 20, 21 |
| SSH | 암호화된 원격 접속과 명령 실행 | 22 |
| Telnet | 원격 터미널 접속. 데이터가 평문으로 전달됨 | 23 |
| SMTP | 메일 전송 | 25 |
| DNS | 도메인 이름과 IP 주소 조회 | — |
| POP3 / IMAP | 메일 수신·접근 | 110 / 143 |
| DHCP | IP 주소, 게이트웨이, DNS 등의 자동 설정 | 67, 68 |

평문으로 전송하는 Telnet과 FTP는 정보가 노출될 수 있습니다. 웹 자료는 SSH를 암호화된 원격 접속 방식으로 소개합니다.

### 웹 자료의 원격 접속 예시

```bash
ssh test@192.168.10.15
ssh -l test 192.168.10.15 -p 2002
```

두 번째 명령은 사용자 `test`, 대상 `192.168.10.15`, 포트 `2002`를 지정합니다. 주소와 계정은 자료의 예시이므로 실제 접근 권한이 있는 실습 대상에서만 사용하세요.

### 공유 서비스

- **Samba**: SMB를 이용해 리눅스·유닉스 서버와 윈도 컴퓨터 간 파일·프린터 공유를 지원합니다.
- **NFS**: 네트워크를 통해 원격 파일 시스템을 공유하고 마운트하는 방식입니다.
- **RPC**: 웹 자료에서 서비스와 포트를 연결하는 데 사용하는 프로토콜로 소개합니다.

## 2. 네트워크 설정 파일

| 경로 | 웹 자료의 역할 |
| --- | --- |
| `/etc/sysconfig/network` | 호스트명과 게이트웨이 등 기본 네트워크 정보 |
| `/etc/sysconfig/network-scripts/ifcfg-eth0` | 해당 인터페이스의 설정 |
| `/etc/resolv.conf` | DNS 서버 등 이름 해석 설정 |
| `/etc/hosts` | IP 주소와 호스트명 대응 |

예시 설정의 `DEVICE`, `BOOTPROTO`, `IPADDR`, `NETMASK`, `GATEWAY`, `DNS1`, `ONBOOT`는 각각 장치, 주소 설정 방식, IP, 마스크, 게이트웨이, DNS, 부팅 시 활성화 여부를 나타냅니다. `BOOTPROTO=dhcp`는 자동 주소 설정 방식입니다.

> 위 `sysconfig` 경로는 웹 자료의 환경에 대한 예시입니다. 설정을 복사해 적용하기보다 사용하는 배포판의 구성을 먼저 확인하세요.

## 3. 상태 확인

```bash
ip addr show
ping -c 3 192.168.10.1
netstat -r
arp -a
ss
```

| 명령 | 확인 대상 |
| --- | --- |
| `ip addr show`, `ifconfig` | 네트워크 인터페이스와 주소 |
| `route`, `netstat -r` | 라우팅 정보 |
| `ping` | 대상의 응답 |
| `traceroute` | 목적지까지의 경로 |
| `arp -a` | ARP 캐시 |
| `ethtool 인터페이스` | 물리적 링크와 인터페이스 정보 |
| `ss` | 네트워크 연결 상태 |

`192.168.10.1`은 웹 자료의 예시 주소입니다. 결과는 실제 네트워크에 따라 달라집니다. 주소나 경로를 변경하는 `ifconfig`, `route` 명령은 연결을 끊을 수 있으므로 먼저 조회만 해 보세요.

DNS 확인 명령 `nslookup`, `dig`, `host`는 [1과목 기타 명령어](../../1과목/3.%20리눅스의%20기본%20명령어/3.%20기타%20명령어.md)에서도 살펴볼 수 있습니다.

### 웹 자료의 조회 흐름

1. `ip addr show`로 인터페이스와 주소를 확인합니다.
2. `netstat -r`로 목적지에 사용할 경로와 게이트웨이를 살펴봅니다.
3. `ping -c 3 192.168.10.1`처럼 확인할 대상에 세 번 요청합니다.
4. 응답이나 경로에 문제가 있다면 `traceroute`로 경유 경로를 살펴봅니다.

예시 주소는 해당 환경에서만 의미가 있으므로 자신의 실습 환경에 맞는 대상을 확인해야 합니다. 응답이 없다는 사실만으로 원인을 단정하지 않습니다.
